## 导航角标一致性（最终根因）
- **根因**：静态 HTML 里设的 badge 数字（内容创作=4/线索洞察=2/客户问答=3/运营复盘=5）会被 `mcn-sidebar.js` 的 `updateBadges()` 在运行时覆盖。`updateBadges` 按 `defaults[key].filter(isUnread).length` 计算「未读数量」，`isUnread` 取决于 `localStorage`(`mcn-workbench-read-notifications-v1`) 已读状态 → 所以不同会话/点击后数字会变，且点进某页会把该项标已读、数字归零隐藏，造成「各页不一致」。
- **修复**：把 `updateBadges()` 改成直接 `return`，不再动态改写导航角标；导航角标固定显示静态 HTML 中的数字（已统一为 4/2/3/5，首页项无 badge）。页面内部未读小红点逻辑（`decorate()`，走 `data-notification-key`）不受影响、保留。
- **版本号**：mcn-sidebar.js 升到 `v=20260728-9`（5 个页面同步）。
- **注意**：之前那次「统一 badge 数字」的批处理其实被正确应用了（静态 HTML 全为 4/2/3/5），只是被 JS 覆盖才显得没生效。

- **版本号**：mcn-sidebar.js 升至 `v=20260728-14`（5 个页面同步）。
- **教训**：复制页面逻辑到共享组件时，务必逐项对照原页面的**数据筛选条件**（如 person 过滤），否则会出现"内容多出/缺少"的不一致。

## 浮动任务组件折叠/弹层点不开（IIFE 作用域 bug）
- **问题**：浮动面板里"✓ 上午已完成 N 项 · 点击展开"的折叠栏点了没反应（任务卡片的必做/选做弹层同样点不开）。
- **根因**：浮动任务组件的所有逻辑（TASKS、TYPE_NAME、COL_NAME、fmt、renderFabTimeline、toggleFabFold、openFabTaskPop）都写在第二个 `(function(){ ... })();` IIFE 内，属于局部作用域。而渲染出的 HTML 用内联 `onclick="toggleFabFold(this)"`、`onclick="openFabTaskPop(event,TASKS.find(...))"` 在全局作用域执行，找不到这些标识符，于是点击无效（控制台报 ReferenceError）。
- **修复**：在 IIFE 闭合前把关键函数与数据挂到 window：`window.TASKS/TYPE_NAME/COL_NAME/fmt/toggleFabFold/openFabTaskPop=toggleFabFold/openFabTaskPop;`。内联 onclick 即可正常调用。CSS 折叠样式本身没问题（`.fold-body{display:none}` / `.fold-body.open{display:block}`）。
- **版本号**：mcn-sidebar.js 升至 `v=20260728-16`（5 个页面同步）。
- **教训**：给共享组件注入带 `onclick="fnName(...)"` 的 HTML 时，fnName 必须是全局（window）可见的；包在 IIFE 里的函数/变量对全局 onclick 不可见，需显式挂到 window。
